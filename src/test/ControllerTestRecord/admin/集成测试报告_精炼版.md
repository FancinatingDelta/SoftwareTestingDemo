# Admin Controller 集成测试报告（精炼版）

## 1. 测试计划概览

| 维度 | 内容 |
|------|------|
| **测试目标** | AdminOrderController（订单审核）+ AdminUserController（用户管理CRUD） |
| **测试类型** | 集成测试（@SpringBootTest + MockMvc） |
| **技术栈** | JUnit 5 + Spring Boot Test + @Sql数据准备 |
| **测试策略** | 判定覆盖 + 边界值分析 + 时序组合测试 |

---

## 2. 测试用例设计亮点

### 亮点一：完整CRUD生命周期时序组合（用户管理）

| 步骤 | 接口 | 时序依赖 | 验证技术 |
|------|------|----------|----------|
| 1 | `checkUserID.do` | 无 | 判定覆盖（true分支：用户不存在） |
| 2 | `addUser.do` | 步骤1通过后 | 重定向验证 |
| 3 | `userList.do` | 步骤2完成后 | 循环遍历分页查找 |
| 4 | `modifyUser.do` | 步骤3获取id后 | 参数替换验证 |
| 5 | `delUser.do` | 确认用户存在后 | 清理验证 |

**典型代码**：`userLifecycle_shouldCompleteCrudSequence()`
- 使用时序戳生成唯一userID避免冲突
- 跨接口数据传递验证（id获取→修改→删除）
- 真实数据库操作，非Mock

### 亮点二：多维度边界值覆盖（订单审核）

#### 参数边界覆盖矩阵

| 参数 | 有效类 | 无效边界值 | 测试技术 |
|------|--------|-----------|----------|
| `orderID` | 1001（存在待审核） | 0, -1, 99999（不存在） | 边界值分析 |
| `page` | 1 | 0, -1, 999999 | 边界值 + 等价类 |

**典型用例**：`passOrder_shouldReturnTrue_whenOrderAlreadyAudited`
- 等价类：已审核订单（state=2）再次审核
- 发现：Service层未做状态校验（记录为风险证据）

### 亮点三：SQL预置数据策略

```sql
-- 一条SQL脚本支撑多个判定用例
INSERT INTO `order` (orderID, state, ...) VALUES (1001, 1, ...); -- 待审核（true分支）
INSERT INTO `order` (orderID, state, ...) VALUES (1002, 2, ...); -- 已审核（false分支）
-- 99999不存在（false分支）
```

## 3. 核心技术决策

| 决策 | 说明 |
|------|------|
| `@Transactional` | 每个测试后自动回滚，避免数据污染 |
| `@Sql` 前置执行 | 每个测试方法独立准备数据，保证隔离性 |
| `assertThrows(Exception.class)` | 验证异常路径，不伪造异常处理 |
| 动态时间戳 | `System.currentTimeMillis()` 确保并发测试安全 |

---

## 4. 发现的风险点

| ID | 描述 | 测试证据 |
|----|------|----------|
| R1 | 订单审核无状态校验（已审核可再次审核） | `passOrder_shouldReturnTrue_whenOrderAlreadyAudited` |
| R2 | 添加用户未校验空参数 | `addUser_shouldHandleEmptyParams` 返回重定向而非错误 |
| R3 | 分页参数0和负数未在Controller层拦截 | `getOrderList_shouldThrowException_whenZeroPage` |
